## 1. 作業ブランチの運用ルール
- 必ず `main` ブランチまたは`main`ブランチから派生した作業ブランチを起点にして新しく作業ブランチを作る。
- 直接 `main` ブランチにプッシュしない。

---

### 1.1 命名規則
- **言語**: ブランチ名は必ず**英語**で命名する。
- **書式**: 小文字のハイフン繋ぎ(`kebab-case`)で記述する。
- **禁止事項**: ブランチ名に**絵文字(Gitmoji)や記号(`:`, `#` など)は使用しない。**

---

### 1.2 プレフィクス一覧
- 作業内容に応じて、以下のプレフィクスを必ず使用する。
- 以下に存在しないプレフィックスを使用する場合は、このドキュメントも更新する。

| 作業内容 | プレフィクス | ブランチ名の具体例 |
| :-- | :-- | :-- |
| **新機能の追加** | `feature/*` | `feature/counter-reset` |
| **バグ・表示崩れの修正** | `fix/*` | `fix/counter-reset-bug` |
| **コード整理・リファクタリング** | `refactor/*` | `refactor/clean-counter-logic` |
| **READMEなどのドキュメント更新** | `docs/*` | `docs/update-branch-rule` |
| **cssによるレイアウト調整のみ** | `design/*` | `design/convert-flex-to-grid` |

## 2. コミットの運用ルール
変更内容を明確にし、履歴を追いやすくするために、以下のルールに沿ってコミットメッセージを記述する。

※ 原則として、ブランチと同様に`main`ブランチに直接コミットをプッシュしない。

---
### 2.1 命名規則
- **言語**: コミットメッセージは**日本語**で記述する。
- **形式**: 先頭に `プレフィクス:` を半角で付け、スペースを1つ空けてから内容を記述する。
    - 例: `feat: 削除ボタンと個別消去機能を追加`
- **禁止事項**: コミットメッセージの先頭や途中に**絵文字（Gitmoji）は使用しない。**（履歴の検索性を保つため）
- **粒度**: 「1つのコミットには1つの作業」を意識し、まとめて大量の変更をコミットするのは避ける。
    - コミットメッセージが1トピックにできない作業はコミットを分ける。

---

### 2.2 プレフィクス一覧
- 作業内容に応じて、以下のプレフィクスを必ず使用する。
- 以下に存在しないプレフィックスを使用する場合は、このドキュメントも更新する。

※ 新機能追加の際、ブランチ名は `feature/` 、コミットは `feat:` になる点に注意する。

| 作業内容 | プレフィクス | コミットメッセージの具体例 |
| :-- | :-- | :-- |
| **新機能・要素の追加** | `feat:` | `feat: 削除ボタンを追加` |
| **バグ・表示崩れの修正** | `fix:` | `fix: カウンターのリセットバグを修正` |
| **コード整理・リファクタリング** | `refactor:` | `refactor: イベントリスナー周辺のコードを整理` |
| **READMEなどのドキュメント更新** | `docs:` | `docs: ブランチとコミットの運用ルールを追記` |
| **CSSによるレイアウト・デザインの調整** | `design:` | `design: カウンターの配置をFlexからGridに変更` |
| **構文・インデント統一** | `style:` | `style: カウンターの配置をFlexからGridに変更` |
