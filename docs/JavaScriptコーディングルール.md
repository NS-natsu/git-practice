## 1. 実装方針とアーキテクチャ

### 1.1. クラス(`class`)の禁止

- オブジェクト指向的なクラス構文は使用しない。
- 状態の管理は[HTML実装ガイドライン](HTML実装ガイドライン.md#2-タグ選定の基本4原則)で定義する**状態の保持をするタグ**または**クロージャ・関数スコープ**で行う。
- 処理は純粋な関数ベースで構築する。

---

### 1.2. イベントデリゲーションの徹底

要素ごとに個別にイベントハンドラ(`addEventListener`)を登録するのは避け、共通の親要素(例: `main` や `window`)でイベントを1箇所でキャッチし、条件分岐で処理を振り分ける。
- ハンドラのスコープを狭めると、動的に追加された要素(`<template>` から生成された要素など)に対してもイベントを網羅的に登録する必要があるため。
- 親要素の判定には `closest` を使用し、自身の要素の特定には `matches` か `classList`を使用する。

---

## 2. コーディングスタイル

### 2.1. ネスト
最大で4層までとし、超える場合はガード節やサブルーチン化によって解消する。

---

### 2.2. 命名

- 原則としてすべてローワーキャメルケース（camelCase）を使用する。
- 役割とデータ構造を正確に一致させるため、以下のルールを厳守する。
- 動詞を使用する場合は、汎用性の高すぎる動詞(`do` など)はむやみに使わず、その処理の「本質」や、値の「状態」に最も適した英語の動詞・助動詞を選択する。

| 対象 | ルール | 具体例 |
| :-- | :-- | :-- |
| 関数 | 必ず「何をするか」を示す動詞で始める | `createCounterElement` <br> `setupCounterButtonBehavior` |
| オブジェクト変数 <br> (連想配列・配列・DOM) | データの中身か型がわかる名前にする <br> **名詞または形容詞**で構成する | DOM要素: `counterElm` <br> 配列: `counters` (複数形) <br> マッピング: `keyActions` |
| プリミティブ変数 <br> (数値・文字列・真偽値) | 原則として **データの中身か型がわかる名前**にする <br> 状態やフラグを表す場合に限り動詞(助動詞)ではじめる | `isPlus` (真偽値フラグ) <br> `titleStr` (文字列) |

---

### 2.3. 関数の命名に使用する動詞・助動詞例

| 動詞 | 用途・意味 | 具体例 |
| --- | --- | --- |
| **`create`** | 新しいDOM要素やオブジェクトを**生成して返す**処理 | `createCounterElement` |
| **`setup`** / **`init`** | 初期設定やイベントハンドラの登録などの**仕込み・準備** | `setupCounterButtonBehavior` |
| **`handle`** / **`on`** | イベント発火時に実行される**対話・応答**の処理 | `handleCounterKeydown` |
| **`get`** | 既存のデータや状態を**取得・算出する**（戻り値がある） | `getCounterValue` |
| **`update`** | 画面の描画や内部のデータを**最新の状態に更新する** | `updateDisplay` |
| **`toggle`** | ON/OFF(表示/非表示など)の**状態を交互に切り替える** | `toggleEditMode` |
| **`validate`** | 入力値や形式が正しいかを**検証・チェックする** <br> Booleanは返さず失敗時にErrorを投げる手法をとる <br> 値を返す場合はBooleanではなく検証済みの値を返す | `validateTitleInput` |
| **`is`** / **`has`** | 対象が特定の状態であるかを検査し、**Booleanを返す関数** | `isCounterLimit` |

---

### 2.4. プリミティブ変数の命名に使用する動詞・助動詞例

※オブジェクト変数には動詞を使用しないため、この表は「Booleanなどのプリミティブ値」を対象とする。

| 動詞/助動詞 | 用途・意味 | 具体例 |
| --- | --- | --- |
| **`is`** | 「**〜であるか**」（現在の状態、等価、同一性のフラグ） | `isPlus`, `isMinus`, `isReset` |
| **`has`** | 「**〜を持っているか**」（要素、属性、データが存在するフラグ） | `hasError`, `hasActiveChild` |
| **`can`** | 「**〜できるか**」（実行可能、操作可能かどうかのフラグ） | `canClick`, `canEdit` |
| **`should`** | 「**〜すべきか**」（特定の処理を行う必要があるかのフラグ） | `shouldUpdate`, `shouldRender` |

---

## 3. 関数定義と並び順ルール

### 3.1. トップレベル関数は `function` キーワードを使用する
ファイルの最上位(トップレベル)で定義する関数は、アロー関数(`const foo = () => {}`)ではなく、必ず**`function` 宣言**を使用する。

---

#### 3.2. 関数の定義はファイル末尾に「実行順(呼び出される順)」に並べる

コードは「上から下へ」読めるように並べる。
- 関数はJavaScriptの関数の巻き上げ(Hoisting)特性を活かし、処理をファイルの上部、関数の定義はファイル下部に集約する。
- 関数の定義順は、処理の実行順に、より早く呼び出される関数が上に記述されることを徹底する。
  - 実行順がユーザの操作に依存する場合はどちらが先でもよい。

```js
// 1. 初期化処理・エントリーポイント(上に書く)
document.querySelector("main").appendChild(createCounterElement());

/* その他処理の記述
    ...
*/


// 2. メインの関数(次に書く)
function createCounterElement() {
  const counter = ...;
  setupCounterButtonBehavior(counter); // 下の関数を呼び出す
  return counter;
}

// 3. 末端の補助関数(下に書く)
function setupCounterButtonBehavior(counter) {
  ...
